# Accessibility

The HRIS must be accessible for daily government work across offices, devices, and user roles.

## Standards

- Use semantic HTML in future implementation.
- Keep keyboard navigation complete.
- Maintain visible focus states.
- Provide sufficient color contrast.
- Do not rely on color alone for status.
- Use text labels with icons.
- Keep form labels connected to controls.
- Provide error summaries and inline errors.
- Support screen reader-friendly table headers and form groups.

## Status and Alerts

Status badges must include text. Alerts should be announced in a way compatible with assistive technologies when implemented.

## Forms

- Required fields must be marked with text or accessible attributes.
- Help text should be associated with fields.
- Validation messages should identify the field and issue.
- Multi-step workflows should announce current step and completion state.

## Tables

- Use meaningful column headers.
- Avoid horizontal scrolling when a card/list alternative works better on mobile.
- Provide accessible labels for row actions.

## Modals and Drawers

- Trap focus while open.
- Return focus after close.
- Provide clear close controls.
- Avoid using modal-only workflows for long forms.

## Motion

Keep animation subtle. Avoid motion that is necessary to understand workflow state.
